## 项目深挖类

### RAG 项目里最难的点是什么
中文检索召回质量。单纯向量检索对中文术语、缩写召回差。我用混合检索解决：向量召回（语义）+ 关键词召回（中文 bigram 分词 + pg_trgm 字面匹配），再用 RRF 倒数排名融合，最后 Rerank 精排，评测集验证 Recall@K 有明显提升。

### 为什么用 RRF 融合而不是加权求和
因为两路召回的分数尺度不同：向量路是余弦距离，关键词路是命中次数，直接加权要调权重且不稳。RRF 只关心排名（1/(k+rank) 求和），免调参、鲁棒，k 取常用值 60。

### 分块策略是怎么定的
Markdown 按标题（##/###）切成结构块，保证块有语义边界；长块再按长度二次切分，用滑动窗口 + 句末标点优先，相邻块保留重叠避免边界信息丢失。块大小与重叠都做成配置（max-chars / overlap）。

### Agent 模式是怎么实现的
ReAct 风格循环：LLM 输出 THOUGHT/ACTION/ACTION_INPUT/ANSWER，解析后分派工具（语义检索/关键词检索/列文档/读文档），结果按全局编号回填，最多 5 步；最终答案的 [N] 与引用来源严格对应。还有"过早放弃"拦截——模型说"没找到"但实际没检索时，强制补一次语义检索再答。

### 引用溯源怎么保证准确
所有工具命中的片段统一收集去重，按全局编号回填上下文，最终答案里 [N] 与返回的 sources[N-1] 一一对应，前端可点击查看原文章节，避免模型编造引用。

### 评测闭环是怎么做的
建评测集（问题 + 期望关键词 + 参考答案），跑 Recall@K（命中期望关键词比例）+ LLM-as-judge 打分，生成 HTML 报告可回溯每题；差评经点赞/点踩反馈回流，人工复核后扩充评测集，形成数据驱动优化。

### 健身训练记录小程序是怎么做的
它是微信小程序原生 + CloudBase 云开发的形态，刻意不引入独立后端。技术含量最高的是"数据口径自洽"：训练日只由 workouts 决定、指标由 workouts+sets 联合计算并过滤未完成组与孤儿组、日期口径统一走一个 dateKey 函数，保证日历/首页打卡/统计三处永远对得上。写入安全上做了三道闸门——字段白名单防透传、更新删除检查影响条数防假成功、并发写走事务防覆盖。训练 Agent 走云函数调 LLM，模型不可用时降级为本地规则建议。

### 两个项目的数据层为什么差这么多
定位不同。FitLog 是个人训练记录，数据量小且敏感，用 CloudBase 文档库 + 云函数免运维、账号体系(_openid)开箱即用，复杂关联靠云函数聚合而非 SQL JOIN；rag-kb-demo 要做通用知识库问答且必须做向量语义检索，所以选 PostgreSQL + pgvector 同库存结构化与向量，HNSW 索引支撑召回。一个求轻、一个求检索能力，技术选型都服务于各自场景。
