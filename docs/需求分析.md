> 本文档是后续开发(后端改造 / 内容蒸馏 / 前端设计 / 评测 / 部署)的需求依据;与 PLAN.md 冲突时以本文档为准,审阅后冻结;**实现细节(接口/配置/部署)与技术方案.md 冲突时,以技术方案.md 为准**。

## 1. 项目概述

将 `E:\WorkBuddy\rag-kb-demo`(RAG 知识库问答系统)改造为**个人 AI 分身网站**:

- 用结构化 Markdown 知识库"蒸馏"用户真实经历(简历 + 项目);
- 部署到公开 URL(香港轻量服务器 + 域名,免备案);
- 投简历时面试官先访问网站:一页式浏览简历 → 与**第一人称"我是本人"**口吻的 AI 分身对话,可深挖项目细节/技术方案/行为问题;
- 回答**只基于知识库事实,不编造**;敏感问题礼貌拒答;超出知识库范围如实说明。
- 上线前以"面试官高频问题"评测集(30-50 题)把关,通过率 ≥90%。

## 2. 目标与背景

| 项 | 说明 |
|----|------|
| 业务目标 | 投简历时给面试官一个"先看先问"的入口,AI 分身替候选人应对初步提问,提升面试效率和候选人第一印象 |
| 技术目标 | 复用 rag-kb-demo 的成熟 RAG/Agent 能力(已测试),展示候选人的工程能力(混合检索、Agent 化多步问答、评测闭环) |
| 成功标准 | ① 面试官访问后能自然地问出真实面试问题并得到准确回答;② 评测集通过率 ≥90%;③ 单次对话成本可忽略(限流 + token 上限) |

## 3. 用户角色与使用场景

### 3.1 角色

| 角色 | 说明 | 权限 |
|------|------|------|
| 面试官/HR(访客) | 收到简历链接的人,匿名访问 | 浏览落地页、与 AI 分身对话;无注册、无上传、无管理 |
| 站长(本人) | 网站所有者 | 经隐藏管理页(JWT 登录)查看访客提问历史与反馈统计 |

### 3.2 典型场景

1. 候选人投递简历时附上网站链接(如 `zhengziheng.me`);
2. 面试官打开链接 → 落地页看到候选人画像(简介/技能/项目/经历/联系方式入口);
3. 面试官点击"向 TA 提问"进入聊天页,提问"介绍一下你做过的 RAG 项目",AI 分身第一人称回答并展示引用出处;
4. 面试官开启"深度思考"(Agent 模式),追问"这个项目最难的点是什么?怎么解决的?",AI 分身多步检索-反思-再检索后作答,界面展示思考过程动效;
5. 面试官问"期望薪资/身份证号"等 → 护栏拒答并引导"这类信息建议直接与候选人本人沟通";
6. 面试官问题超出知识库 → 如实说明"简历/经历中没有相关内容";
7. 站长登录管理页,查看访客提问记录与反馈,据此扩充 FAQ 与知识库。

## 4. 功能需求

### 4.1 访客侧(公开,免登录)

#### F1 落地页(一页式简历)
- 模块:顶部简介(姓名/定位/一句话)、技能栈(分类标签)、项目展示(含 fitlog/rag 等,可点击外链)、实习/工作经历时间线、教育背景、其他经历(竞赛等)、联系方式入口(邮箱/微信等,由站长决定展示哪些)、简历下载(PDF,可选)。
- 醒目 CTA:"向 TA 提问"按钮,进入聊天页。
- 数据源:前端配置(真实简历数据,由用户提供;联系信息经部署环境变量注入,不进公开仓库)。

#### F2 聊天页
- 输入框 + 发送;空输入/超长输入(>500 字)前端拦截并提示。
- 示例提问 chip(如"介绍一下你的项目经历""你在 RAG 项目里解决了什么难题"),点击即发送。
- **SSE 流式输出**:打字机效果逐字展示。
- **Agent 思考过程动效**:深度思考模式下,展示"正在检索… / 检索到 N 个片段 / 反思中…"等步骤(复用 rag-kb-demo 的 agent_step 事件机制,重点打磨视觉)。
- 引用来源面板:回答下方展示来源(文档名/章节/相似度),可折叠。
- 多轮上下文:携带最近 ≤10 轮对话(后端追问改写,支持"那它/再讲讲"类指代)。
- 深度思考开关:默认开启(用户决策 Q14:Agent 模式开放,重点打磨流式效果);normal 模式为快速兜底。
- **身份明示**:聊天页头部明确标注"AI 分身·基于本人真实经历作答"(不只页脚声明),避免访客误以为在与本人实时对话。
- 语言:纯中文界面;回答纯中文(用户决策 Q15)。

#### F3 回答边界(护栏)
- 只答知识库事实;证据不足时如实说明,不编造(用户决策 Q8/Q7)。
- 敏感词护栏:仅拦"索取本人隐私"意图(薪资/身份证/联系方式等),技术词(密码/验证码/微信等)不拦,提示词级拒答 + 输出脱敏兜底。
- 第一人称"我是本人"口吻,以站点公开展示名"郑梓恒"自称(非法定真名,隐私无碍)(用户决策 Q8 + 追加决策)。

#### F4 限流与提示
- 每 IP 限流(默认 50 问/小时,可配——按面试官深度追问 + 同公司 NAT 共用出口 IP 留足余量);超限返回友好提示("提问太频繁啦,请稍后再试"),不封禁页面浏览。
- 登录接口 `/api/auth/login` 单独更严限流(默认 10 次/小时/IP),防暴力破解站长密码。
- 单次回答 token 上限(默认可配,如 800),防止单次超支。

### 4.2 站长侧(隐藏管理页,JWT 登录)

#### F5 访客提问记录
- 列表查看最近问答(问题/回答/时间/来源),支持搜索与分页。
- 复用 rag-kb-demo 的 qa_log 表(访客问答匿名落库,`username='anonymous'`);**不提供公开历史接口**(原 `/api/chat/history` 移除,防访客数据串号,见技术方案 §4.7),访客会话由前端 localStorage 持久化;站长经新增的 `GET /api/admin/qa` 接口查看全部访客提问记录。

#### F6 反馈与统计
- 点赞/点踩 + 评论(复用 feedback 表与接口);统计看板(总量/好评率/最近差评)。
- 差评问题一键"扩充到 FAQ 候选"提示(人工确认后写入知识库)。

#### F7 知识库更新流程(站长操作手册的一部分)
- 流程:修改/新增 `resources/kb/*.md` → 重新部署或触发重建接口 → 索引更新(按 content hash 幂等)。
- 提供"重建索引"的管理接口(权限:站长)。

### 4.3 系统能力(复用 rag-kb-demo)

| 编号 | 能力 | 说明 |
|------|------|------|
| F8 | 文档分块入库 | Markdown 按标题分块 + 长度二次切 + 重叠窗口(MarkdownParser + ChunkSplitter) |
| F9 | 混合检索 | 向量 + 关键词,RRF 融合(HybridRetrievalService) |
| F10 | Rerank | 启发式默认(零成本),可切 LLM 策略 |
| F11 | LLM 流式生成 | OpenAI 兼容协议(DeepSeek),SSE |
| F12 | Agent 化问答 | ReAct 多步:检索→反思→再检索→生成,工具:语义检索/关键词/列文档/读文档(AgentChatService) |
| F13 | 启动 seed | 启动时从 `resources/kb/*.md` 幂等灌入(按 doc 名 + content hash 去重),重启不重复 |
| F14 | 评测闭环 | 评测集 + Recall@K + LLM-as-judge + HTML 报告(EvalService,站长侧触发) |

### 4.4 隐藏(不对访客开放,但保留能力)
- 文档上传、文档列表/详情/删除(访客不可见;站长管理页亦不暴露,仅保留接口或后续启用)。
- 评测页、反馈统计页:仅站长经管理页访问。

## 5. 非功能需求

| 类别 | 需求 | 指标/说明 |
|------|------|-----------|
| 性能 | 落地页首屏 | <3s(静态资源,CDN 可选) |
| 性能 | 普通问答首字响应 | <3s(不含 LLM 排队) |
| 性能 | Agent 深度思考全流程 | <30s(多次 LLM 调用,接受) |
| 可用性 | 移动端适配 | 面试官可能手机访问;落地页 + 聊天页响应式 |
| 可用性 | 浏览器兼容 | 现代浏览器(Chrome/Edge/Safari 近 2 年版本) |
| 安全 | 密钥管理 | DeepSeek/Embedding key、JWT secret 全部环境变量注入,gitignore,仓库零密钥(旧 .env.example 中泄露的 key 作废轮换) |
| 安全 | 个人信息 | 仓库不含手机号/邮箱/地址;联系信息走部署环境变量/私有配置 |
| 安全 | 滥用防护 | 每 IP 限流(50 问/时)+ 单次 token 上限 + 登录接口限流(10 次/时/IP,防爆破,随 M1 实现) |
| 安全 | 传输 | HTTPS(certbot),全站强制跳转 |
| 成本 | LLM 调用 | DeepSeek 约 ¥1-2/百万 token;站内默认 Agent(约 2-3 次调用/问),normal 为快速兜底;限流 50 问/时/IP + 单次 token 上限(800)兜底 |
| 成本 | Embedding | 硅基流动 bge-m3,知识库仅数篇 md,月度成本可忽略 |
| 可维护性 | 内容更新 | 改 md → 重建索引;文档化操作手册 |
| 可维护性 | 日志 | 问答日志(qa_log)、错误日志;LLM 调用失败降级(抽取式/提示) |
| 合规 | 隐私声明 | 落地页页脚标注"本站为 AI 分身,内容基于本人简历与项目经历,如有出入以本人为准" |

## 6. 内容需求(蒸馏)

### 6.1 知识库文档清单(第一阶段)
| 文档 | 内容 |
|------|------|
| 01-个人简介.md | 一句话定位、自我介绍、求职意向 |
| 02-教育背景.md | 学校/专业/学历/时间(占位待填) |
| 03-实习与工作经历.md | 每段经历:公司/岗位/时间/职责/成果(占位待填) |
| 04-项目-rag-kb-demo.md | 项目深挖(见 6.2 模板) |
| 04-项目-fitlog-backend.md | 项目深挖 |
| 05-技能栈.md | 技术栈清单 + 熟练度自述 |
| 06-常见面试问答.md | FAQ:自我介绍/项目深挖/八股/行为题(30-50 题骨架) |

### 6.2 项目深挖模板(每项目一篇)
背景 → 我的职责 → 技术选型与架构 → 核心难点(2-3 个)→ 解决方案 → 量化成果(如有)→ 复盘与可追问点。

### 6.3 简历数据字段清单(落地页数据)
姓名(是否公开由用户定)、定位、联系方式(环境变量注入)、教育、技能、项目(标题/描述/链接/技术栈)、经历、其他经历、社交链接(GitHub/博客/掘金等)、头像/背景图。

### 6.4 FAQ 骨架(30-50 题,分四类)
- 自我介绍类(5-8 题):"做个自我介绍""为什么选后端/这个方向"
- 项目深挖类(10-15 题):"RAG 项目最难的点""为什么用 RRF""分块策略怎么定的""Agent 模式怎么实现的""测试怎么设计的"
- 技术八股类(10-15 题):Java/Spring/Vue/数据库/Redis/网络 高频题
- 行为类(5-10 题):"最大的挫折""怎么学习新技术""职业规划"
> 注:八股类内容若知识库未收录,AI 分身将如实说明"简历经历中未涉及"——FAQ 骨架由我起草,是否收录八股答案由用户决定。

## 9. 验收标准

### 9.1 功能验收(上线前逐项勾选)
- [ ] 落地页模块齐全、数据为真实简历
- [ ] 聊天页流式输出、思考动效、引用面板、示例问题、多轮指代正常
- [ ] 护栏生效:敏感问题拒答;知识库外问题如实说明
- [ ] 限流生效:问答超限提示友好;登录接口连续超限返回 429
- [ ] 管理页可登录、可见提问历史与反馈统计
- [ ] 知识库 seed 幂等:重启不重复入库
- [ ] 移动端可用

### 9.2 质量验收
- [ ] 面试官高频问题评测集 30-50 题,通过率 ≥90%(EvalService:Recall@K + LLM-as-judge,差评题人工复核)
- [ ] 后端原有测试通过(mvn test),前端构建通过(vue-tsc + vite build)

### 9.3 上线检查清单
- [ ] 旧 .env.example 泄露的 key 已作废轮换
- [ ] 仓库无个人信息、无密钥(git grep 检查)
- [ ] HTTPS 生效、全站跳转
- [ ] 限流/护栏/管理页鉴权验证通过
- [ ] 隐私声明页脚上线

## 10. 边界与不做(Out of scope)

- 多语言(纯中文);换技术栈;面试官注册/登录;访客上传文档。
- 三个旧简历站的代码迁移(仅按需提取素材);真实简历之外的项目深挖(用户后续自选补充)。
- 移动端 App / 小程序;本地离线演示环境。
- 多实例水平扩展 / Redis 限流(单机内存足够)。
- 采集访客个人身份信息(匿名访问,仅 IP 限流计数,不留存访客隐私)。
