# 知识库蒸馏模板

> 用途：新增一个项目/经历到知识库时，按此模板写一篇 md 放入 `backend/src/main/resources/kb/`，重启或触发 `/api/admin/kb/rebuild` 即生效。
> 现有 MarkdownParser 按标题（##/###）分块，模板的每个二级标题会成为一个检索单元，保证"可追问点"能被单独命中。

## 背景与目标
（一段话：这个项目解决什么问题、为什么做）

## 我的职责
（我具体负责的部分，独立/协作）

## 技术选型与架构
（技术栈 + 关键架构决策，说清"为什么这么选"）

## 核心难点与解决方案
（2-3 个最值得讲的难点，每个：问题 → 方案 → 取舍）

## 量化成果
（数据/指标/交付物，如测试数、性能提升、规模）

## 复盘与可追问点
（面试官可能追问的角度 + 参考答案要点：为什么用 A 不用 B、边界在哪、如果重做会怎么改）

---

## 编写要点（让 AI 分身回答得像个真人）
1. **具体 > 抽象**：写"用 RRF 融合解决两路分数尺度不同"而不是"做了检索优化"。
2. **含数字**：测试数量、数据规模、性能指标，面试官追问时更有底气。
3. **可追问点要预设答案**：把"为什么不用 X"这类反问提前写出来。
4. **第一人称视角**：内容以"我"的经历写，AI 分身直接引用。
